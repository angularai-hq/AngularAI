<p>One tool a pass, inside one directory: <code>list</code>, <code>read</code>, <code>search</code>, <code>edit</code>, <code>write</code>, <code>run</code>. A path that leaves the directory is refused, including a symlink that points out. <code>list</code> and <code>search</code> skip one. A secret in a file is redacted before the next pass. The log keeps the task and the tool of each step, not what the tool returned. A log written before this version may still hold tool output. Nothing is deleted. The step budget is 8. The reply is the only line on stdout.</p>
<p>A tool&#39;s output reaches the model between <code>BEGIN TOOL OUTPUT</code> and <code>END TOOL OUTPUT</code> markers with a random tag, as data, never as instructions. A malformed tool call is refused, not repaired: a wrong type, an unknown field, or a field over its limit is named back to the model, and nothing runs. A remembered fact is judged like a reply, so a locked phrase or a secret is never kept.</p>
<p>Files are opened one path component at a time without following links, so a path swapped for a link after the check is refused. A read refuses anything but a regular file (a FIFO, a socket, a device) and never blocks on one. It stops at 4 MiB, and a line at 2,000 characters. A file with a NUL in its first 8 KiB, or that is not UTF-8, is binary: only its size is reported. <code>search</code> reads at most 1 MiB a file, 16 MiB in all, and stops walking after about 20,000 entries. <code>list</code> shows 80 of at most 5,000. A write goes to a new file renamed over the name, keeping its mode, so a hard link to the old file, inside or out, keeps the old content. A read cannot tell a hard link from the file, and follows it. <code>edit</code> takes files up to 80,000 bytes.</p>
<p><code>run</code> is off. <code>--allow-run</code> turns it on for that command.</p>

<p>With <code>--allow-run</code>, <code>run</code> starts one program from an allowlist: <code>basename cat cmp cp cut dirname echo false grep head ls mkdir mv pwd rm rmdir sort stat tail touch true uniq wc</code>. There is no shell, no interpreter, no <code>find</code>, <code>xargs</code>, <code>env</code>, <code>git</code>, or <code>make</code>. The program comes from <code>/usr/bin:/bin</code>, never from the directory. Every argument that names a path must resolve inside the directory. Options that run a program or follow a link out are refused: <code>cp -L -H --dereference</code>, <code>grep -R --dereference-recursive</code>, <code>sort --compress-program</code>, <code>--files0-from</code>. The program starts in the directory with three variables: <code>PATH=/usr/bin:/bin</code>, <code>HOME</code> set to the directory, and <code>LANG</code>. No API key is passed. Output stops at 64 KiB. After 20 seconds the whole process group is killed.</p>
<p>This is a filter on what starts, not an operating-system sandbox. No allowlisted program opens a network connection, but nothing at the OS level blocks one. <code>rm</code> and <code>mv</code> can delete or move anything inside the directory, but not the directory itself. <code>run</code> needs Linux or macOS.</p>

<summary>What survives a crash?</summary><p><code>cortex.json</code> is written to a temporary file, fsynced, and moved into place. You see the old file or the new one. A pass is one line in <code>passes.jsonl</code>, written once and fsynced. Writers take a lock on <code>.lock</code> in the cortex, so two processes never mix their lines. The lock is advisory, and on Windows it does nothing.</p>
<p>A line that cannot be read, including a last line cut off mid-write, is skipped. Nothing stops. You are told once which lines, as <code>passes.jsonl:N</code>. They stay in the file until you run <code>angularai repair</code>, which moves them to <code>passes.jsonl.corrupt</code> and keeps the rest. Nothing is deleted.</p>
<p><code>cortex.json</code> carries <code>version</code>. A cortex without it is version 1. An older version is migrated when the cortex opens, and the old file is kept as <code>cortex.json.v&lt;N&gt;</code>. A newer version is refused and left as it is.</p>
</details><details>
<summary>Does clearing the screen forget?</summary><p>No. <code>/clear</code> clears the screen. The cortex stays on disk.</p>
</details><details>
<summary>What comes back later?</summary><p>“What color is the notebook?” finds “The notebook is blue.” “What shade is it?” shares no word with it and does not. With embeddings on, “When is lunch?” finds “Catering is at noon.” by meaning. “What shade is it?” names no notebook. With OpenAI&#39;s <code>text-embedding-3-small</code> it scores 0.25, under the 0.35 a match needs, so it still misses.</p>
</details><details>
<summary>What does recall by meaning send?</summary><p>Nothing, unless <code>ANGULARAI_EMBEDDINGS</code> is set. Then <code>say</code>, the session&#39;s turns, <code>angularai recall</code>, and <code>recall</code> in angularai-mcp send the question and each trace not yet embedded, redacted, to the embeddings endpoint. <code>remember</code> in angularai-mcp sends the new trace. Episodes and tool output are not sent. A trace is embedded once. A trace whose cosine with the question is 0.35 or more ranks by that, at most 8 of them, and is sent to the model only if it fits the budget. In <code>recall</code> its score shows as <code>~0.49</code>. <code>angularai recall --lexical</code>, <code>/recall</code> in the session, and <code>angularai agent</code> match words only.</p>

<summary>What counts as a secret?</summary><p>A known key shape: OpenAI, Anthropic, GitHub, Stripe, Google, AWS, GitLab, Hugging Face, Slack, a JWT, a PEM private key. A literal value after <code>password=</code>, <code>token:</code>, <code>api_key=</code>, and kin. A run of 32 or more key characters that mixes cases and digits and is random enough. Hex hashes and UUIDs are not. The value of an environment variable whose name holds KEY, TOKEN, SECRET, PASSWORD, PASSWD, or CREDENTIAL: eight characters or more anywhere, six or seven with a digit or a symbol as a whole word. A shorter or all-letter value is ignored. A secret in the input is refused. Anywhere else it is redacted or held. A key in a shape Angular AI does not know passes.</p>
</details><details>
<summary>What if the API is slow or busy?</summary><p>Connecting waits 10 seconds. Each read waits 90. A pass gets 180: no attempt or wait starts after that, and each read timeout is cut to what is left. A call is tried at most 3 times. Only a rate limit, a 5xx, an overloaded API, a timeout, or a failed or dropped connection is tried again. A rejected key, a 400, a 403, a 404, or a billing error is not. The wait is what the provider asked for in <code>Retry-After</code> or <code>retry-after-ms</code>, else a random wait up to 1, 2, 4… seconds. No wait is longer than 30 seconds. A longer <code>Retry-After</code>, or one that would pass the deadline, ends the pass. A retry is sent before any reply exists, so the pass is written and counted once.</p>

<summary>What does a failure look like?</summary><p>No cortex yet: <code>angularai init</code>. A secret in the input: it is refused before the key is looked up. No key: the missing variable is named, and the value is never printed. A rejected key, for OpenAI: <code>The substrate (OpenAI) rejected the API key.</code> No quota or no billing: the provider&#39;s code is named, for example <code>insufficient_quota</code>, and waiting will not help. A rate limit: you are told to wait, for the seconds the provider asked for when it says. An overloaded or failing API: you are told so, with the provider&#39;s message, redacted and cut at 200 characters. The API is down, or the reply is not the JSON object Angular AI asked for: nothing new is remembered. The input is over the budget: it is not sent. A lock phrase or a secret in the reply or its tool: you see <code>Value lock held this reply.</code> The held text is not stored, and a held reply does not run a tool. A trace the model was not shown is not superseded. When the step budget is spent, the last reply is printed and the cortex keeps that pass.</p>
